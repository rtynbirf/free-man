# Политика безопасности

## Поддерживаемые версии

| Версия  | Поддержка |
| ------- | --------- |
| 0.2.x   | да        |
| < 0.2   | нет       |

## Как сообщить об уязвимости

Только приватно, через GitHub: **Security → Report a vulnerability**
(https://github.com/rtynbirf/free-man/security/advisories/new).

Электронной почты, формы обратной связи и мессенджеров у проекта нет —
это часть канона: нет аккаунта, нет сервера, нет каналов сбора. Публичный
issue до триажа открывается только для нечувствительных дефектов UX.

Приложить: версию расширения, шаги воспроизведения, ожидаемое и фактическое
поведение, по возможности — минимальный PoC.

Сроки: подтверждение получения — до 7 дней; после триажа — оценка и
ориентировочный срок фикса; публичное раскрытие — после выпуска фикса,
по согласованию с докладчиком.

## Что считается уязвимостью

- Любой исходящий сетевой запрос расширения к сторонним серверам: проект
  декларирует «нет телеметрии» — исходящий трафик из service worker это
  ломает.
- Обход или ослабление блокировки без явного действия пользователя
  (динамические allow-правила, выставленные не через кнопку «Пауза»).
- Доступ третьей стороны к `chrome.storage` расширения.
- Инъекция DNR-правил, не порождённых `tools/build_rules.py` из
  `data/domains.json` (источник единственный, биекция сверяется CI).
- Выполнение удалённого кода: в MV3 оно запрещено архитектурой; любой
  обход — критическая уязвимость.
- Запрос разрешений шире заявленных в `manifest.json` без действия
  пользователя (`<all_urls>` — только optional, только при включении GPC).

## Что не считается уязвимостью

- Fingerprinting и серверный first-party трекинг: это граница метода
  (DNR по доменам её не закрывает), задокументирована в README, раздел
  «Границы».
- Ограничение Chrome на частоту `getMatchedRules` (~20 вызовов за 10
  минут) и его доступность только у распакованных расширений.
- Разлогин после «Стереть данные сайта» — задокументированное следствие
  очистки.
- Продолжающаяся блокировка запросов внутри iframe сторонних виджетов
  при включённой паузе — известное ограничение.

## Канон данных

Правила не редактируются руками: `data/domains.json` — единственный
источник, `rules/*.json` генерируются `tools/build_rules.py`. Изменение
списка доменов — правкой источника; расхождение сборки с источником
роняет CI.
